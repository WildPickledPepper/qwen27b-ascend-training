# Adam 严格 FP32 第五阶段真实小模型状态的无损压缩

2026-10-24，Asia/Shanghai。仅在独立 CPU 研究环境 CPU 运行独立 NumPy 网络和标准库 zlib，未下载权重、安装依赖、执行第三方优化器、连接远程设备或启动 NPU。

## 结论

从真实闭环训练而非独立随机浮点数中取出 FP32 m/v 后，本轮仍未发现接近 200.39→30 GiB 所需压缩率的方法。21,508 参数 tanh 网络、三种子、七时间点共 21 份状态，246 个无损格式检查全部逐位 roundtrip 通过。

成熟训练状态的最好编码约占原始存储的 82.7%–82.9%，主要是 byte shuffle + zlib。目标要求约 14.97%，两者差距很大。但这不是“所有无损方法不可能”或“27B 状态必定如此”的证明，只能排除本轮具体方法和具体训练样本达标。

## 真实状态来源

沿用第四阶段独立生成的分类数据和固定 teacher，将 student 隐藏层扩为 1024：16→1024→4 tanh，含偏置，有效参数 21,508。每组种子训练 4096 步，batch=64，peak lr=0.001、64 步 warmup、余弦衰减到 1%，beta=(0.9,0.999)、epsilon=1e-8、weight decay=0.01。

只使用完整 FP32 Adam 状态，不启用上一阶段的有损格式。前向/反向为自写 NumPy 代码，Adam 运算顺序与此前逐位对照的参考一致。训练4096/验证2048/测试2048数据独立；本次采样没有使用测试结果进行选择。

在第 1、2、128、1024、2048、4095、4096 步，保存更新后的真实 m/v。每份快照是 172,064 bytes，即有效参数×8，不包含为了小块执行而添加的填充坐标。文件按 m 后 v、小端 FP32 原始字保存，附 SHA256、形状、种子和训练步数。

## 试验格式及完整计费

所有 frame 包含 32-byte 固定头和 175-byte 来源/形状元数据，本模型共 207 bytes。原始 baseline frame 为 172,271 bytes。下表为三个种子第 4096 步的比值，分母是含相同基本元数据的原始 frame。

| 无损格式 | 存储比范围 | 完整 frame bytes 范围 |
|---|---:|---:|
| 原始数据 zlib level 9 | 0.9126–0.9131 | 157221–157293 |
| byte shuffle + zlib | 0.8272–0.8285 | 142503–142733 |
| sign/exponent/mantissa 分流 + zlib | 0.8292–0.8304 | 142854–143058 |
| 32 个 bit plane + zlib | 0.8343–0.8360 | 143729–144015 |
| 同状态相邻字 XOR + shuffle | 0.8340–0.8344 | 143668–143743 |
| m² 预测 v、保存 XOR 残差 | 0.8690–0.8697 | 149704–149832 |
| 分块拟合系数×m² 预测 v | 0.8693–0.8701 | 149750–149891 |
| 时间 XOR，包含完整原始锚点 | 1.6973–1.7100 | 292396–294577 |
| 时间 XOR，包含完整最优压缩锚点 | 1.5252–1.5377 | 262750–264898 |

另测 zlib level 1/6，所有结果保留在 CSV。拟合预测器每 256 参数保存一个 FP32 系数，连同块长和系数数目共 348 bytes，已包含在 frame 中。预测结果不是直接丢弃残差，而是保存 FP32 原字 XOR，所以所有原始位都能恢复。

时间差分并未借用未计费的历史：frame 内嵌完整锚点 frame、锚点长度和 SHA256，再存 XOR 差分。第 4096 步对第 4095 步是相邻更新，仍因完整锚点而超过原始体积。相距更远的快照同样逐项计费。没有把磁盘或主机存储隐藏成免费参考。

## 初期漂亮结果为什么不代表训练全程

第 1 步，分块拟合 m² 预测 v 的比例为 0.4974–0.4984。零初始化后的首个梯度使 m 与 v 有特殊的代数关联，因此可压缩性较高。

到第 2 步，最好方法已退化到约 0.8465–0.8484；第 128 步最好约 0.8399–0.8411；第 1024 步以后主要在约 0.827–0.830。首步结果不能代表成熟状态，更不能直接外推到大模型。

## 分布与精度位的瓶颈

第 4096 步没有零状态元素。三个种子的 m 尾数低 8 位经验熵为 7.897–7.913 bits，v 低 8 位为 7.991–7.992 bits；中间 8 位约 7.991–7.992 bits。相对而言，指数经验熵仅约 m 2.98–3.00 bits、v 2.60–2.73 bits。

这解释了为什么把指数、符号和字节分开能省一些空间，而保留全部尾数位很难在这些样本中获得巨大收益。这里的边际/独立位熵不是整体状态熵下界，更不是对更强预测器、模型间结构或大模型的不可压缩性证明。跨坐标/跨层依赖尚未穷尽。

## 工作内存不能漏算

压缩比例表只描述完整持久 frame，不能代表实际峰值。此规模 encode+decode 的 tracemalloc 峰值，byte shuffle 约 802 KB，cross-m² 拟合约 1.40 MB，float-fields 约 9.01 MB，bitplanes 约 11.65 MB。这个 Python 实现会构造中间数组，因此后两种尤其不能直接套用先前 8 MiB 设备工作区假设。

tracemalloc 不覆盖全部原生 zlib 工作区或进程 RSS；没有声称本轮已实现设备流式编码或已测得显存节省。若要部署，仍须独立验证分块编码、索引、旧/新状态过渡、分配器和原生 codec 工作区。

## 检查与文件

- 246 个真实快照/格式组合均验证恢复后的字节串与输入完全相等，并核对 SHA256。
- 另以 +0、−0、次正规数、±infinity 和不同 NaN payload 检查所有 12 种编码，逐位通过。带预测算术的格式是在相同 NumPy/IEEE 环境中验证，没有额外认证跨平台 NaN 算术的规范化行为。
- 每份原始状态及每份最优非时间编码都随包保存，其他候选保留精确长度、耗时、工作内存和恢复检查结果，均可重新生成。

## 约束核对与下一步

用户训练仓库的研究约束明确写有“不做 CPU 卸载”；它不是仅仅偏好 GPU resident。仓库没有单独授权磁盘/NVMe 外部后备存储，不能把磁盘当成绕开该约束的默认方案。30 GiB 指当前讨论的 m/v 显存目标，不应改写为全机器总内存限制，也不能把卸载称作压缩。

在未得到更新授权前，建议下一步只测试同设备概念下的有界分块无损更新：用一份压缩状态存储区与固定工作窗口，逐块解码、精确更新和写回，并计入索引、长度变化、最坏情况回退和旧/新交接。CPU 只充当算法实验载体，不把外部主机/磁盘当免费状态仓库。预期只能验证约 15%–20% 的样本存储收益能否保留到实际工作峰值，不能许诺达到 30 GiB。外部后备流式方案不属于当前范围；如另行考虑，须先明确授权与预算边界。
