# Stage 7：小型注意力检索任务，公平的低比特 AdamW 对照

## 先说结果

- 30 个预定实验全部完成且无非有限值：3 个数据/初始化种子 × 2 个共同学习率 × 5 种状态表示，各 4,096 步。
- FP32 测试准确率为 99.17%–99.66%，量化状态为 99.07%–99.66%。逐种子、同学习率配对差为 **−0.195 到 +0.098 个百分点**。测试交叉熵配对变化为 −0.00347 到 +0.00240，比例 0.722–1.197。没有稳定的 q 优于 m 的结论，更不是数值无损。
- 确实在做检索：换成序列里另一个、类别不同的键作为查询，模型对旧标签准确率降至 0.44%–1.47%，对新目标保持 98.09%–99.36%；不是记住一个固定键的类别。
- 序列化状态小，但当前 Python/NumPy 实现不省实际工作区：完整保留缓冲区的优化器循环追踪峰值，FP32 103,845 B，量化格式 398,694–410,062 B（含共享码本）。优化器 CPU 时间约 15.9–20.2 倍，整体约 2.01–2.47 倍。
- 这是非常小、较容易的合成 exact-match 检索任务，不能外推为真实 Transformer、27B 模型或 NPU 证据。

## 任务与可复现协议

每个样本有 7 个新生成的单位长度 8D 键，每个键独立随机分配 4 类之一的值，最后一个 token 的查询等于均匀选中的某个键。固定教师是点积最近键的 hard attention，然后复制该键的值；生成时逐样本断言教师取回的确实是被选键。没有外部数据、模型权重、下载代码或新安装依赖。

学生使用最后查询的双头注意力（宽度 16、每头 8），输出投影，加查询残差，再接 16→32→16 tanh FFN 和残差，最后分类到 4 类。不是完整语言模型或自回归 Transformer。

重要参数计数更正：**2,180 是声明的模型坐标，不全是数据活跃坐标**。Wq 有 112 个、Wk/Wv 各有 64 个结构性零梯度项，共 240 个，故 1,940 个数据活跃坐标。另有 124 个布局填充项，实际状态有 2,304 个坐标。全部 30 个最终状态中，结构性零梯度项和填充项的 m/v 均保持精确零。实际字节比较始终按真实分配的 2,304 计，不按 1,940 假装不存在其他状态。

- 种子 101/202/303；每个种子独立 train 4096、validation 2048、test 2048。
- 每个 split 用独立固定 RNG；跨 split 样本键集合不重复。每个序列内部的键值分配重新生成，不能用固定词表背答案。
- 相同种子中，各方法的初始化、数据、64 大小 minibatch 顺序完全一致；4,096 步即 64 个完整训练 epoch。输入、初始化和批次 SHA-256 全部保存并重现。
- 共同学习率峰值 0.001 / 0.003，64 步预热，随后余弦降至峰值的 1%；不按测试集挑选方法、学习率或最佳 checkpoint。
- 都是 AdamW：β1=.9、β2=.999、epsilon=1e-8、解耦 weight decay=.01，不剪裁梯度。FP32 master weights。
- 模型、梯度、moment recurrence 和参数更新为 FP32；报告均值，以及码本 log 插值、概率和随机均匀数使用 FP64。不能说整个实现全是 FP32 运算。
- 早期 512 步 pilot 曾看过旧 seed101 测试数组，其源码/结果留在 initial_pilot_preserved。正式协议在全量运行前改为独立 split RNG，故正式 train/val/test 数组均不同；随后独立 seed909 pilot 验证同一已预定结构及学习率，无基于测试结果的调参。此历史明确保留，不把已看过的数组说成盲测。

## 状态表示

复用 stage3 自行实现的正式 16 级 NF4（包括 ±1）、有精确零码的 4-bit 正值 log-v，以及随机舍入 SR。每块持久元数据为三个 FP32 值：signed scale、正 v 最小值、v 最大值，共 12 B。全局头 32 B 含步数、长度、块长、seed 和格式；共享 NF4 码本 64 B。没有补偿缓存或额外 FP32 状态。

m/v 方案保存 m 与 v；q/v 方案保存 q=m/(sqrt(v/c2_t)+epsilon)，其中 c2_t=1−β2^t。重构 m=q_decoded*(sqrt(v_decoded/c2_t)+epsilon)，随后新梯度仍按同一个 FP32 AdamW recurrence 更新。c1_t=1−β1^t 在当前更新中单独处理。epsilon 的位置没有改变。

signed SR 在当前两个码值间做线性概率；v 的 SR 按当前 f(v)=1/(sqrt(v/c2_t)+epsilon) 配概率。后者是局部条件性质，不代表递归状态、闭环参数轨迹或完整训练无偏，更不代表精确等价。

## 注意力依赖检查

- 评估时把注意力强制均匀，准确率 44.14%–47.51%。这是一种干预，不是另行训练的强基线。
- 不能把 25% 随机猜类当作唯一无查询基线：只看七个值的多数类，在此分布的精确期望准确率为 45.5078125%；三个实际测试集为 47.36%、46.34%、43.36%。
- 更有力的配对检查是保持 context 完全不变，只把 query 换成另一个类别不同的 context key。旧标签准确率 0.44%–1.47%，新目标 98.09%–99.36%。只统计可换到不同类别的样本，数量逐行记录。
- 两头均值的 attention top-1 检索准确率 99.76%–100%；目标 attention 质量约 0.585–0.651。
- 30 个最终模型各检查 128 个样本的 context 排列置换，预测全部不变。浮点求和顺序造成的小 logit 漂移单独记录。

## 真实字节与工作区，不能混为一谈

| 格式 | 序列化状态 | 另计共享码本 | 完整保留缓冲区循环的 Python/NumPy 追踪峰值，含码本 |
|---|---:|---:|---:|
| FP32 | 18,464 B | 0 | 103,845 B |
| m/v B64 | 2,768 B | 64 B | 402,974 B |
| m/v B128 | 2,552 B | 64 B | 398,694 B |
| q/v B64 | 2,768 B | 64 B | 410,062 B |
| q/v B128 | 2,552 B | 64 B | 407,974 B |

memory.csv 是原始的孤立单步新分配探针，不是完整峰值。为免漏算先前仍存活的 m/v/d 等数组，audit_attention.py 从初始化前开始追踪 16 步相同 decode→moments→update→encode 循环；memory_loop.csv 包含保留的零初始化数组、旧/新 m/v、方向 d、编码临时数组、已分配的新权重副本与 packed state。

它排除开始前已有的输入权重/梯度、模型前反向及数据，是优化器循环的追踪测量，**不是训练进程 RSS，也不是 GPU/NPU 显存测量**。tracemalloc 未覆盖的原生分配不假装已测。全局 Python 运行时与配置解释器开销也不等于原生设备格式元数据。2,304 坐标整窗执行，未实现生产级分块 kernel。

规模设计沿用 stage3 的条件预算：8 MiB 工作区加 1 MiB 张量布局预留，在 200.39 GiB FP32 m/v 口径下，B64 约 29.754 GiB，B128 约 27.406 GiB。它们仍是原生平坦打包的设计值，不是本 Python 峰值，不是本阶段已验证的 27B 内存承诺。本任务中的 padding 和 240 个死坐标也不能拿去外推真实模型压缩能力。

## 结论与下一步

低比特 m/v 和 q/v 在这个易检索的注意力任务里均能保持接近参考的任务质量，但它们仍是有损方案，且 NumPy 当前实现以更大临时内存和更长时间换取较小的持久字节。没有理由继续用接近满分的玩具准确率冒充严格 FP32 解答。

下一步建议转向严格的时间换空间验证：在显式可重放的合成外生梯度条件下，从 seed/时间/坐标重算历史梯度并逐位恢复 FP32 m/v，统计完整时间、栈和临时内存；再用参数耦合目标检验“拿当前权重代替历史权重算旧梯度”的失败边界。可重放梯度 oracle 必须明确列为假设，不能冒充已经解决真实神经网络历史梯度重建。
