# Adam 状态压缩第三阶段审计与压力测试

2026-10-24，Asia/Shanghai。仅在独立 CPU 研究环境 CPU 运行独立 NumPy 实验，未安装或执行第三方优化器代码，未接触 NPU、远程训练或原模型。原阶段脚本、报告和 CSV 均原样保留。

## 结论

1. 第二阶段不能用于否定官方 SOLO、ZIP-SR 或 ZE-EDEN。它们是本地规则变体，共享自定义确定性 DE m 码本，并非完整论文复现。该码本有 +1、没有 −1，负方向块最大值被缩小 11.25%。本阶段改用含 ±1 的正式 NF4 查表值作对照。
2. 第二阶段的 29.96125 GiB 是附带未实现流式选择器假设的设计数，不能覆盖现有 Python 实现。实际大 k 选择峰值约 216.5 bytes/项；改用 224 bytes/项保留量后，即使仍保留其他理想化流式假设，也变成 30.10802 GiB，超过目标。
3. 用 q=m/(sqrt(v/c2)+epsilon) 与 log-v 联合编码，在相同字节预算下改善部分梯度流；但确定性 q 在对角二次函数上的漂亮结果没有经受旋转压力测试。不能把它宣布为精度更高的 Adam。
4. 随机舍入 q/NF4+log-v、块长 64 的设计峰值为 29.75430 GiB。旋转二次函数 8192 步后目标值为配对 FP32 的 1.40–2.34 倍；加固定共享梯度噪声后为 1.089–1.141 倍。尚不接近证明 27B 训练可用，更不是无损替代。

## 第二阶段审计

### m 码本和实验公平性

原 m 码本把 −1 重建为 −0.887499988，+1 则保持精确。恒定负梯度持续 1024 步，仅对 m 使用该编码时，量化前 m 达到参考的 0.496894 倍。这是具体编码的偏差，不是 NF4 或论文方法的普遍结论。

原阶段的 beta=(0.9,0.999)、lr=1e-4、epsilon=1e-8、decoupled weight decay=0.01，以及初始化和输入种子在配对组间一致。m-only / v-only 确实将另一侧保留 FP32，它们只是消融，不能列为 30 GiB 方案。原 SOLO-style 还使用本地自定的零分位数下限；保留既有名称中的 style 边界，不升级为正式复现。

原 FP32 1024 步目标值为 1.216e-4–1.815e-4，仍为初始值的 1.24%–1.49%。这个分母不是最优值，更不是神经网络损失下限。原本的 5.49–18.84 倍只描述固定步数的具体测试结果。

### 零值、epsilon 和无偏边界

原 ZIP 局部规则允许正 v 舍入为零。epsilon 在根号外，能避免除零，但不能阻止偶发大更新。原 SOLO-style 的正值对数格加下限策略不能精确保留混合零块。原 ZE-EDEN 的无零化也不保证更新可靠。

ZIP 概率公式只对当前已给定 v 的实数函数 f(v)=1/(sqrt(v/c2)+epsilon) 做条件无偏插值。它不使 v 本身无偏，不使下一步非线性递推无偏，也不等价于整条 Adam 轨迹或逐位 FP32。实际输出、尺度和运算的 FP32 舍入还会进一步破坏严格实数等式。

### 异常块保护峰值的修正

原窗口审计检查了选择后的少量结果，没有测大 k 选择过程。独立测量 heapq.nlargest：k=8192/65536/131072 时选择峰值为 209.5/215.4/216.5 bytes/项。两个输出项的 304 bytes 不能直接外推，因为包含固定容器开销；本结论以完整选择过程的峰值为依据。

27B 设计中选择 1,641,602 个块，原预算仅剩 39.68 MiB。将每项选择结构保留量从 128 改为 224 bytes，设计总量由 29.96125 改成 30.10802 GiB。因此拒绝“现有 Python 原样扩展仍在 30 GiB 内”的结论。224 是根据本机测量向上取整的保留量，不是所有解释器和所有 k 的证明上界。

一个每项小于等于 128 bytes 的紧凑原生选择器仍可能保留原数学预算，但尚未实现。现有脚本还有整向量解码和 join 构造异常列表；它们也不能被当成已完成的生产流式内核。

## 第三阶段编码与验证

持久状态严格是序列化字节，不保留 FP32 补偿、误差反馈或隐形状态缓存。比较 m/v 和 q/v 两种坐标：

- m/v：4-bit NF4 或对称 15 级均匀码编码 m，4-bit 正值对数格编码 v。
- q/v：先计算 q=m/(sqrt(v/c2_t)+epsilon)，再用同一有符号码本编码 q；重建 m_hat=q_hat*(sqrt(v_hat/c2_t)+epsilon)。c2_t=FP32(1−0.999^t)，当前更新另有 c1_t=FP32(1−0.9^t)。这里存的是未除 c1 的 q，不混淆 bias correction。
- 每块有一个 FP32 有符号尺度和两个 FP32 v 正值端点，共 12 bytes。v 的 0 码专门表示真零，其余 15 码在正端点间按对数插值；零块、常数块、混合零块、FP32 最小正次正规数均通过检查。
- RTN 是有符号值最近舍入及 v 对数最近舍入。SR 是有符号值的线性无偏随机舍入及 v 的当前预条件器函数条件无偏随机舍入。本轮 RTN/SR 对比同时切换两侧，不能单独归因于 m 的舍入。
- 64-bit seed、step 和全局坐标构成计数型 PRNG，不保存 NumPy 随机数生成器状态。头部 32 bytes，NF4 共享查表 64 bytes。

NumPy FP32 参考与原标量参考在四类输入、各 32 步上的 m、v、更新、权重逐位一致。三个对角 toy 输入哈希与第二阶段完全一致。NF4 只借用公开查表常数，没有下载或执行其优化器实现。

## 字节预算与质量曲线

目标 P=26,895,998,464。原 FP32 m/v 数据为约 200.391 GiB。新持久数据为 P + 12*ceil(P/B) bytes，另加 32-byte 全局头、64-byte 共享码本、8 MiB 工作窗口保留量和 1 MiB 张量布局/元数据保留量。

1 MiB 布局保留量可覆盖例如不超过 1000 个张量、每张量不超过 1024 bytes 的描述符、尾块、头部及对齐开销。实际模型布局未逐项验证；不能把这个假设写成已测量。工作窗口取 16384 参数，实测相关 tracemalloc 峰值约 2.39–2.76 MB，低于 8 MiB。此计量不是进程 RSS，更不是 Ascend 分配器或内核峰值。模型权重、梯度、激活不在 m/v 替代预算内。

| 块长 | 持久位/参数 | 含保留量设计 GiB | 30 GiB 目标 | q/NF4 SR 对角 1024 步目标比范围 |
|---:|---:|---:|---|---:|
| 32 | 11.000 | 34.45096 | 不合格 | 1.565–1.809 |
| 64 | 9.500 | 29.75430 | 条件满足 | 1.708–2.254 |
| 128 | 8.750 | 27.40597 | 条件满足 | 2.302–2.922 |
| 256 | 8.375 | 26.23180 | 条件满足 | 2.384–2.954 |

没有因块长 32 质量更好而忽略其超预算。256 参数的真实序列化长度为 B=64 时 336 bytes、B=128 时 312 bytes，另有共享码本；实际打包而不是用 uint8 数组假装 4 bits。

## 为什么没有宣布确定性 q 获胜

相同 27.40597 GiB 格式，NF4 m/log-v RTN 在对角 toy 的目标比为 6.51–11.14，而 NF4 q/log-v RTN 为 0.073–0.205，看起来有明显进步。随后固定三种子，测试 Householder 旋转的相同特征值二次函数、共享噪声及较长时间：

| 方案 | 对角 1024 步 | 旋转 8192 步 | 旋转加噪 8192 步 |
|---|---:|---:|---:|
| m/NF4 SR B64 | 1.914–2.362 | 1.346–3.249 | 1.207–1.330 |
| q/NF4 RTN B128 | 0.073–0.205 | 13.249–50.966 | 0.998–1.336 |
| q/U15 RTN B128 | 0.061–0.179 | 7.645–116.791 | 1.085–1.317 |
| q/NF4 SR B64 | 1.708–2.254 | 1.398–2.339 | 1.089–1.141 |

表中都是相同种子、相同 lr=1e-4、相同步数的配对目标比。旋转 8192 步时 FP32 的绝对目标为 9.03e-9–7.14e-8；q/NF4 RTN 为 1.56e-7–9.46e-7，q/NF4 SR B64 为 1.26e-8–1.37e-7。加噪时 FP32 为 3.40e-6–3.59e-6，q/NF4 SR B64 为 3.88e-6–3.95e-6。

学习率同时给参考与量化组扫 5e-5、1e-4、2e-4、4e-4，未只替压缩方案调参。对角 1024 步、lr=4e-4 时 FP32 为 4.48e-11–7.22e-11，q/NF4 RTN 为 4.20e-11–1.16e-10，原先的数量级优势不再存在。完整结果记录绝对目标、初始归一化目标、梯度范数、距已知最优点距离和相对 FP32 权重 RMS。由于 weight decay，数据目标最优点不等于优化器的严格固定点。

固定梯度重放也不能只看巨大相对数：near_cancel 的参考更新范数可低至 5.48e-7。q/NF4 SR B64 的单步相对误差超过百万，但全时段累计更新 L2 相对误差约 0.180–0.183；单坐标最大更新差为 0.154–0.168，对应 lr=1e-4 的参数步差为 1.54e-5–1.68e-5。这个失败不能忽略，也不能只用接近零的分母制造夸张结论。

## 文件和复现

从本目录运行，安装环境需已有 NumPy，本阶段未安装依赖：

```bash
python audit_stage2.py
python run_stage3.py --out results --replay
python replay_diagnostics.py
python stress_stage3.py
```

- `stage2_audit.json`：码本、选择峰值、原始文件哈希和审计边界。
- `results/toy_summary.csv`、`toy_checkpoints.csv`：45 个初筛配置记录。
- `results/replay_summary.csv`：126 个固定输入重放记录。
- `results/replay_diagnostics.csv`：54 个补充绝对误差记录。
- `results/memory.csv`、`audit.json`、`run.json`：实际长度、窗口测量、检查和环境。
- `stress_results/summary.csv`、`checkpoints.csv`、`run.json`：225 个压力测试记录。

部分压力配置重复初筛以确认衔接，不能把它们当额外独立种子。每个闭环场景只有三组数据/初始化种子，随机舍入种子与该种子绑定；不是统计充分的泛化研究。所有编码都是有损设计。
