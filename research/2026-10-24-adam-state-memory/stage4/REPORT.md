# Adam 压缩状态第四阶段非线性监督实验

2026-10-24，Asia/Shanghai。独立 NumPy CPU 实验，无外部数据、第三方优化器执行、依赖安装、NPU 或远程训练。

## 结果

小型非线性网络上，四种低位方案的最终验证交叉熵为配对 FP32 的 0.9735–1.0184 倍，独立测试交叉熵为 0.9554–1.0247 倍。30 次运行均完成 4096 步，没有非有限状态。q 重参数化没有稳定胜过直接 m/NF4 编码，因此不应据此宣布 q 更好。

这个结果比纯二次函数更接近实际训练，但仍只有 1348 个有效参数、3 组 teacher/数据/初始化种子，不能证明 27B 可用、统计等价、无损或普遍精度保持。第三阶段旋转目标上的失败仍然有效，不因这次小模型结果较好而删除。

## 配对协议

- 固定 teacher：16→48→4 tanh 网络，每组种子独立生成固定权重，取 logits 最大值为四分类标签。
- student：16→64→4 tanh 网络，含偏置，共 1348 个有效参数。状态打包补到 1408 坐标，B64 有 22 块、B128 有 11 块；补齐参数不参与前向，梯度严格为零。
- 数据：4096 训练、2048 验证、2048 测试样本，独立随机抽取；三部分没有重复输入。每轮训练是同一组样本的排列，不混入验证或测试。
- 每配置 4096 步，batch=64，即 64 个完整 epoch。所有配对方案使用相同初始化和批序。
- peak lr 分别为 0.001、0.003。前 64 步线性 warmup，此后余弦衰减到 peak 的 1%。beta=(0.9,0.999)，epsilon=1e-8，decoupled weight decay=0.01，FP32 主权重不变。
- 验证每 256 步一次；测试只在预先固定的最终步计算。没有用测试挑选步数或超参，两组学习率和全部结果均保留。
- 对照：FP32、m/NF4+log-v SR B64/B128、q/NF4+log-v SR B64/B128。编码、epsilon、bias correction 和条件无偏边界与第三阶段一致，不添加补偿缓存。

三个种子是 101、202、303；每个种子都改变 teacher、样本及 student 初始化。它们是三组配对问题，不是单一数据集上大量重复随机舍入的统计检验。

## 验证和测试结果

下表为三个种子的最终交叉熵/同种子 FP32 交叉熵范围。小于 1 不代表已证明优于 FP32。

| 方案 | peak 0.001 验证 | peak 0.001 测试 | peak 0.003 验证 | peak 0.003 测试 |
|---|---:|---:|---:|---:|
| m/NF4 SR B64 | 0.9968–1.0072 | 0.9988–1.0090 | 0.9735–1.0004 | 0.9612–1.0247 |
| m/NF4 SR B128 | 0.9986–1.0043 | 0.9994–1.0113 | 0.9820–1.0018 | 0.9554–1.0192 |
| q/NF4 SR B64 | 0.9996–1.0040 | 0.9995–1.0078 | 1.0064–1.0123 | 0.9796–1.0185 |
| q/NF4 SR B128 | 0.9997–1.0063 | 1.0004–1.0129 | 0.9905–1.0184 | 0.9568–1.0112 |

FP32 的绝对验证交叉熵：peak 0.001 为 0.26574–0.31959，peak 0.003 为 0.26105–0.29748；对应验证准确率为 86.57%–89.21%、87.89%–89.70%。全部绝对损失、准确率、梯度范数、最大参数步差和与 FP32 权重 RMS 差异保存在 CSV，而不是只保留比值。

## 存储、工作区和计算成本分开看

实际状态序列化有测量，不用“uint8 代表 4-bit”代替打包：

| 方案 | 本 toy 序列化 bytes | 另计共享活跃码本 | 一次优化器操作 tracemalloc 工作峰值 |
|---|---:|---:|---:|
| FP32 | 11296 | 0 | 45768–45796 bytes |
| m/NF4 SR B64 | 1704 | 64 bytes | 234445–234473 bytes |
| m/NF4 SR B128 | 1572 | 64 bytes | 233301–233329 bytes |
| q/NF4 SR B64 | 1704 | 64 bytes | 240205–240233 bytes |
| q/NF4 SR B128 | 1572 | 64 bytes | 239061–239089 bytes |

头部已含在序列化长度中。FP32 和压缩组都保留相同 1408 个补齐状态坐标；真实有效参数对应的理想 FP32 数据是 10784 bytes，不能把 padding 当压缩贡献。Python bytes 对象分配另在 CSV 记录。工作峰值不含已有参数、输入梯度、持久状态及数据/前向激活；这是工作操作的 tracemalloc 测量，不是进程总 RSS。

所以当前 NumPy 原型减少了持久状态，但在这个小模型上反而增加了优化器操作的分配峰值，不能称为实测峰值省内存。第三阶段面向 26,895,998,464 参数的 B64=29.75430 GiB、B128=27.40597 GiB，仍依赖分块处理、8 MiB 工作区及 1 MiB 布局保留量的条件设计，未转化为生产内核验证。

压缩优化器部分的 CPU 时间为 FP32 的 16.8–24.0 倍，含前后向与定期验证的完整实验时间约为 4.1–5.8 倍。所有配置具有相同训练步数、batch 和评估频率，但目前 NumPy 打包/解码代价很高。这不是速度优化，也不能把这组 CPU 比值外推为设备融合内核性能。

## 检查和可复现文件

- 所有 1348 个有效参数的手写反向梯度与 FP64 中心差分比较，最大绝对误差 5.91e-11；补齐坐标梯度为零。
- 所有训练 epoch 都验证恰好包含训练索引的一次排列；训练、验证、测试输入不重叠。
- 保留每个数据划分、初始化及批序的 SHA256；所有原始阶段文件保持不变。
- 30 次运行共 122880 个小向量优化步骤，不能称为 27B 训练步骤。

从本目录运行：

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python mlp_teacher.py
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python audit_stage4.py
```

依赖已有 NumPy，不需要 PyTorch。数据由脚本重新生成，文件包不包含下载数据。

`results/summary.csv` 为 30 配置最终结果；`checkpoints.csv` 为学习率衰减过程；`memory.csv` 为逐配置工作区；`run.json` 为配置、环境、种子和代码哈希；`full_gradient_audit.json` 为全参数梯度、数据与批序检查。
