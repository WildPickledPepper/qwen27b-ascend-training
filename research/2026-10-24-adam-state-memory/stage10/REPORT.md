# Stage 10 真实梯度因子的有限历史精确重放

## 结论

这次把“保存历史梯度因子，再逐块精确重建 Adam 状态”做成了实际耦合的两层网络实验，而不是外生随机梯度。结果是：**机制可行，短跨度确实省内存；直接重建梯度块也明显避免了重复重建整梯度的成本。但历史存储线性增长，仍不是长期训练的固定低内存解法。**

- 5 个种子、1/2/4/8/16 步、7 种重放配置，共 175 个完成案例。全部权重、m、v、梯度和历史因子原始字节与指定参考一致，共比较 30,089,220 个 uint32 字。
- 另外独立写了一份 NumPy 前向、反向和 AdamW 实现，不调用 C 或 BLAS GEMM。5 条完整 16 步轨迹的全部 2,218,560 个原始字也一致，避免只用共享 C 函数互相验证。
- 分块 B=128、容量 1 步时，扣除共同当前权重后的替代空间是 13,272 B，而原始 FP32 m/v 是 50,304 B，减少约 73.6%。4 步时为 44,232 B，只减少约 12.1%。16 步时为 168,624 B，反而是原始 m/v 的约 3.35 倍。
- 16 步的独立顺序计时中，直接梯度块重建的中位时间比约 2.61×；每个块都重建完整梯度的方式约 95.31×。这是本 CPU 小网络的描述性测量，不是硬件训练吞吐承诺。
- 24 个超容量案例与参考前缀逐字相同；另 24 个独立 arena 对比证明“停在容量处”与“再尝试一步并拒绝”后的权重、历史、临时区和操作计数一致。
- 最省的已测完整案例是容量 1、B=1，仍需要 11,752 B，即原始 m/v 的 23.36%。没有达成 10% 或 15% 级别替代预算，更没有证明 200.39 GiB→30 GiB 的目标。

本阶段源码、编译器来源、反汇编、所有完成和拒绝输出、独立审计及复现脚本都随归档保存。没有修改 GitHub，没有使用用户电脑、状态卸载、Cadence 或新安装的软件。

## 模型和精确性的边界

模型为 D32→H128→输出16 的两层 ReLU MLP，含两层 bias，共 P=6,288 个参数。每次更新包含两个微批，每个微批 4 个样本。数据和初值来自固定种子公式；梯度来自当前真实权重的前向与反向计算，会随训练改变。

AdamW 使用 β1=.9、β2=.999、epsilon=1e-8、LR=.003、weight decay=.01。修正常量采用明确规定的 binary64 十进制幂再转 FP32，原始字随头文件保存。所有核心加、乘、除按规定顺序舍入到 FP32，禁用 fast-math 与 FMA contraction。loss 的报告累加使用 binary64，但不参与梯度或更新。

**这里的逐位精确，严格指同一显式 FP32 K 维归约及微批分组顺序。**它不等于对硬件 GEMM、tensor core、BF16/TF32、融合 AdamW、分布式 all-reduce 或任何框架默认 kernel 的逐位等价。只验证了固定形状、有限步数和这五个种子的有限数值；未覆盖所有 IEEE 特殊值、FTZ/DAZ 或其他舍入环境。

三种模式：

1. 普通参考：保留完整 m/v、当前完整梯度和一个可重用的当前因子记录。
2. 全梯度重放：只暂存一个 tile 的 m/v，但每次历史重放都重建全 P 维梯度，再取该 tile。
3. 直接梯度块重放：只重建该 tile 的梯度，临时区仅有 B 个 m、B 个 v、B 个 g。

每一步在任何权重更新前捕获完整当前记录。后续逐块更新不影响已捕获的当前梯度；旧梯度只读取当年的记录，不用新权重伪造旧激活。m/v 每个 tile 从零开始按时间重放。全历史仍在 RAM 中，没有文件读入、离线 oracle 或隐蔽卸载。正常测量路径不分配完整验证输出。

## 每一步到底存了什么

一个记录共 10,320 B：

- 两个微批的输入 X：1,024 B。
- 隐层激活：4,096 B。
- 隐层反传因子 dZ：4,096 B。
- 输出反传因子 dY：512 B。
- 144 个 bias 的聚合梯度：576 B。
- step、accumulation、microbatch、format 四个 uint32：16 B。

数值载荷共 10,304 B。旧 JSON 的 factor_float_bytes=4 表示单个 float 大小，不是全部因子载荷。bias 没有被漏掉：其历史梯度在每一步记录中，m/v 和权重照常按 tile 重建与更新，所有 bias 字也包含在逐位对比内。

记录按预留容量计费，而非按已经完成的步数。容量 16、只执行 1 步时，仍收费 165,120 B 历史，其中 154,800 B 尚未使用。不能拿第一步实际写入量冒充整个训练的内存上界。

## 空间记账

当前权重完整保留，4P=25,152 B。原始 m/v 为 8P=50,304 B。

用 C 表示预留历史容量，B 表示 tile 大小，δ 表示 malloc_usable_size 减请求字节。已编译应用代码最大活跃调用链为 968 B，包括仍存活的 main，而不是只取最大单个栈帧。

直接分块的替代空间为：

10,320C + 12B + 448 + 968 + δ 字节。

其中 448 B 是 Run 元数据 136 B、数值常量 168 B、额外常量池包络 128 B、分配块头包络 16 B。再加回 25,152 B 就是报告的总算法空间。全梯度重放把 12B 换成 8B+25,152，其他项目不变。普通参考总算法空间为 112,344 B，包含完整当前梯度，不是最优融合实现的下界。

实际 malloc 可用容量逐例记录，包含 mmap/页粒度的额外空间，不能一律设 δ=0。例如 B128、容量16，实际可用块比请求多 552 B；一些其他容量/块形状多出数千字节。

这个包络不等于进程 RSS 或设备显存。它不包括代码、加载器、共享库、stdio、计时基础设施、整个 malloc arena/tcache、OS 映射以及 libc 内部调用栈。反汇编中确实存在清零用的 memset；968 B 是命名应用帧的和，并非 libc 内部栈的完整上界。分块内存结论必须保留这些计量边界。

## 时间和空间结果

下面统一使用 B=128，历史容量恰等于请求步数。时间比来自正确性测试后单独进行的顺序基准：5 个种子、每配置 7 次，配置顺序由固定种子打乱。比值先对同种子的参考计算，再取中位数。

| 步数 | 直接分块替代字节 | 含当前权重的总字节 | 替代空间/原始m/v | 直接分块时间比 | 全梯度重放时间比 |
|---:|---:|---:|---:|---:|---:|
| 1 | 13,272 | 38,424 | 26.38% | 0.87× | 9.96× |
| 2 | 23,592 | 48,744 | 46.90% | 1.07× | 14.67× |
| 4 | 44,232 | 69,384 | 87.93% | 1.27× | 25.57× |
| 8 | 85,512 | 110,664 | 169.99% | 1.73× | 43.81× |
| 16 | 168,624 | 193,776 | 335.21% | 2.61× | 95.31× |

16 步直接分块的种子间时间比范围 1.86×–3.14×；全梯度重放范围 70.05×–113.15×。运行于共享虚拟 CPU，未固定 CPU 亲和性，因此不可把小幅低于 1× 当作已证实的通用加速。正式正确性矩阵的计时也保留，但摘要采用后续单独基准。

在 16 步时，直接分块共执行 855,168 次坐标 moment 转移，是参考 100,608 次的 8.5 倍；墙钟没有同倍数增长，因为两者还共同支付真实网络前向/反向成本。全梯度重放额外把同一历史全梯度为每个 tile 重建一次，造成明显浪费。

最小 B=1 的短跨度空间结果为：1 步 11,752 B；2 步 22,072 B；4 步 42,712 B。缩小 tile 不是免费午餐，其函数调用和重复循环更多；在大分配下页粒度也可能吞掉小 payload 差异。

## 正确性与拒绝测试

预先固定种子为 0、1、42、2026、2147483647；跨度 1/2/4/8/16；全梯度模式 B128/511；直接分块 B1/32/128/511/6288。包含单坐标、非整除尾块和全参数 tile。

25 个普通参考、175 个完成候选都保存了每步完整原始 states、gradients、factors，而非只比较最终 loss 或哈希。独立 NumPy 实现也按相同语义另写前向、反向、微批梯度和 AdamW，使用逐次 elementwise FP32 运算，不调用 C 或 GEMM。5 个种子的全部 16 步原始输出一致。

容量测试使用 0/1/2/4/8/15，两个种子、两种重放模式，共 24 个拒绝案例。每个拒绝运行的输出长度和全部完成前缀与参考相符。另一个 C harness 把“刚好完成 C 步”和“尝试 C+1 步”两个独立 arena 的权重、记录、临时区、摘要及操作计数完整比较，24 个案例全部通过。容量0是在初始化权重后拒绝第一次更新，不是声称整个内存从未写入。

原程序 adjacent hash 的 atomic 标志仅为辅助证据；完成运行上这些标志默认为 true，不应解释成发生过拒绝测试。这里只保证已知容量不足的前置拒绝，不承诺中途异常的一般事务回滚或从任意 checkpoint 恢复。

预算测试共134个，88个拒绝、46个完成，保留所有结果。6个原始m/v预算比例与边界测试均按编译栈968 B执行；10%预算没有完成案例。审计另证实了预检通过、实际分配页舍入后拒绝的案例。预检可能保守拒绝，所以单个拒绝不是最优可行性定理。

容量后置预算检查发生在 calloc 之后、算法开始之前，因此它防止超额算法更新，但不是“物理内存从未瞬时越线”的硬配额。CLI 的 stack_bytes 由调用方传入，formal driver 固定为审计导出的968；程序不适合作为接受恶意参数的生产资源限制器。

24个独立 arena 案例通过 AddressSanitizer 与 UndefinedBehaviorSanitizer，未报错误。初次开启 LeakSanitizer 的运行因环境 ptrace 不受支持而失败；该次不完整 stdout 和错误日志保留，不计为通过。随后关闭仅 leak 检查的重跑输出 capacity_address_undefined.jsonl 含24个完整通过案例。没有声称 leak 检查通过。

验证阶段另行分配全轨迹输出。16步验证的额外原始载荷约1,774,848 B，还未含分配/stdio开销，明确不计入正常低内存执行。因此带 dump 参数跑完整进程，并不意味着整个进程受打印的 optimizer 数值约束。

## 为什么还不是长期解法

只看这个形状，5 步历史本身就是 51,600 B，已经超过完整 m/v 的 50,304 B；尚未加临时区、栈和元数据。因此任何 tile 都无法让本方案在保留5步及以上历史时低于原始 m/v。容量耗尽后必须停止，不能丢弃旧历史、重置 moments 或用近似滑窗后还称逐位等价。

下一条合理路线是把这种“直接重建块”用于更宽矩阵，先算全层因子容量与真实 token/microbatch 数，再验证目标 kernel 的 FP32归约约定。单层 m×n 权重、每步有效 K 个样本，单纯 X/dY 历史约为每步4K(m+n)字节，m/v为8mn字节，忽略其他开销时的必要短跨度条件是 C < 2mn/[K(m+n)]。宽矩阵可能给出更长有限窗口，但多层激活、bias、共享/不能共享的因子、元数据和临时区仍要完整记账。

这只是可检验的下一方向，不是已经得到的扩大规模结果。想支持更长或无限训练，仍需另一个可被完整记账且精确恢复的历史/检查点机制；不能默认免费 checkpoint、隐蔽卸载或丢弃过去。本阶段到此结束，没有启动无关实验。
