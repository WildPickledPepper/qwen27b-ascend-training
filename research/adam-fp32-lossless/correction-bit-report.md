# m/v 精确恢复的纠正位：容量研究

研究日期：2026-10-23（Asia/Shanghai）。结论：所测试的精确恢复方法都未将 m/v 合计控制在30 GiB；其中一种方法的纠正流确实很小，但它依赖的基底仍很大。没有启动训练、模型前向/反向、优化器训练循环或NPU任务。

## 目标与口径

沿用文本可训练参数 N=26,895,998,464。两份原始FP32矩占200.3908 GiB。30 GiB预算对应：

    m/v合计平均9.58128位/参数；需要6.67969倍无损压缩。
    所有参数每增加1位，就增加3.13111 GiB。

这里按GiB而非十进制GB计算；若30GB指30,000,000,000字节，预算更紧。梯度即用即弃，不计完整模型梯度常驻，但这不改变跨步状态的保存需求。

“纠正流”不等于“总状态”：必须加上其所依赖的u、v、旧权重、码表、索引、例外数据等。当前模型权重W已计入模型预算，不在状态预算重复计算；额外旧权重则必须另计。本研究报告的外推容量尚不含NPU在线工作区、分配器预留或速度代价。

## 一、相邻权重与v已知时，m还需要几位

实数公式可从相邻权重差和v移项得到m，但FP32权重写回会让不同m落到同一权重。实现了一个更精确的纠正编码器：给定W_old、W_new、v、步号和超参数，利用运算的单调性，对非负有限FP32 m位串做二分，找出所有映射到该W_new的候选区间，再保存真实m在区间内的序号。

序号若采用定长码，区间包含K个候选时需要ceil(log2 K)位。若候选有非均匀先验或参数间相关性，可能进一步编码；这里的位数不能称为任意算法的平均下界。

明确定义的算术：FP32分别舍入，β1=.9、β2=.999、ε=1e−8、t=1000，无权重衰减，正m；不是Ascend融合内核。固定m=.001、v=.0001，学习率1e−4：

| W_old | 精确枚举区间内的m候选数 | 定长纠正码/参数 | 按本模型N折算的m纠正容量 |
| ---: | ---: | ---: | ---: |
| .001 | 127 | 7位 | 21.92 GiB |
| .01 | 1,007 | 10位 | 31.31 GiB |
| .1 | 8,049 | 13位 | 40.70 GiB |
| 1 | 64,387 | 16位 | 50.10 GiB |

这些容量还没加v和旧权重。其他被测学习率1e−3至1e−5的固定例子，纠正码为3–20位。权重更新被舍为零的额外例子中，该解码器对全部非负有限FP32候选的纠正码可达30位；这个计数未额外施加状态可达性约束，不能当作实际模型分布下界。

另有4,096个明确分布的合成静态快照，用序号变长位打包得到m纠正流4,971字节，平均9.709位/参数；逐位还原全部m成功。按N外推纠正流30.40 GiB，加原始v则130.60 GiB，仍未计旧权重。合成样本不是模型数据，不能用其平均值预测Qwen。

证据：[脚本](correction_bit_study.py)、[完整JSON](correction_bit_study.json)。检查同时验证区间两端及邻接值，以及编码/解码后uint32逐位一致。

## 二、现成公开FP32 AdamW状态的离线实测

为避免只用随机数据，读取了作者公开的[小模型checkpoint](https://huggingface.co/sup-computer/gatsby-nanogpt-3)。没有实例化网络，也没有执行其仓库代码，只用PyTorch weights_only加载CPU张量。

- 固定仓库版本：fcefc5fbc149f9763bd79475fa9ee793abb62ee3。
- 文件132,227,430字节；SHA256：15d50d8d21ef28f6d7a67ee5e937abdcc9fd8e2fe295959a0680b591e82f5f7b。
- 检查点步号7,750，11,015,040个独立参数，38组m/v张量，均为FP32。
- m/v原始合计88,120,320字节；实际β1=.9、β2=.99，与目标讨论常用β2=.999不同。
- 公开实现按参数维数分成两个优化器组；对齐权重时去除共享参数，核对两组数量及每个张量形状。预测所用的是当前W，没有免费使用上一份W。
- 本次环境：PyTorch2.6.0+cpu、NumPy1.26.4、zstandard0.25.0；压缩使用Zstd级别3。

下表GiB均按“此公开样本的每参数编码大小×目标N”外推，不是Qwen实测，也不是理论极限。所有方法均验证uint32逐位还原。

| 方法 | 状态合计位/参数 | 外推状态GiB |
| --- | ---: | ---: |
| 原始m/v直接Zstd | 57.56 | 180.23 |
| 字节重排后Zstd | 52.21 | 163.48 |
| 高16位基底＋低16位纠正，分流压缩 | 52.22 | 163.49 |
| 当前W线性预测m、m²预测v，保存精确XOR残差 | 55.66 | 174.28 |
| 保留u、v，m用“变化标记＋方向位”精确纠正 | 52.71 | 165.04 |
| 目标 | **≤9.58** | **≤30.00** |

### 高16位基底方案的纠正量

每份FP32拆成高16位和低16位，两者用整数拼接即可完全恢复。这里高16位是截断的BF16位前缀，不保证等于计算所需的最近偶数舍入BF16。

m/v两份低16位合计压缩前44,060,160字节，重排后Zstd为44,061,181字节，几乎没有收益。纠正流合计约32.00074位/参数，外推100.20 GiB；加高位基底后合计163.49 GiB。这个结果针对该拆分/编码，不证明所有联合编码的低位条件熵都如此高。

### 纠正量很小的方案：保留u和v，恢复m

离线计算u=FP32(m/(sqrt(v)+ε))，保存u和v。解码时计算m_pred=FP32(u*(sqrt(v)+ε))。因为除法、乘法舍入，m_pred不总等于m。

该公开样本上，90.6931%的m已逐位相同，其余全部只差一个uint32编码单位。因此保存：

1. 是否需要纠正的位图；
2. 需要纠正的位置加1还是减1的方向位。

两流分别位打包、Zstd，连32字节头共851,048字节，即0.61810位/参数；外推仅1.9353 GiB，全部m逐位恢复成功。三值纠正符号的边缘熵约0.53970位，但该边缘熵不是所有联合编码的下界。

**关键是u和v不能免费：**两份基底重排压缩后仍有71,725,777字节，外推163.11 GiB；加纠正流后165.04 GiB。只报告1.94 GiB会漏掉几乎全部状态成本。此样本没有超过一个编码单位的例外，通用实现需要额外的例外标记和原始位串回退。

若试图从权重差免费获得u，问题会回到第一节：需要旧权重，而且权重写回的舍入再次引入无法直接反解的信息。

### 利用当前W预测的方案

每张量按闭式统计得到m≈aW+b、v≈c*m²的FP32预测，保存真实位串与预测位串的XOR。编码中计入3个FP32系数/张量及索引共768字节，解码时重新从W和系数生成预测，并先恢复m再预测v。该简单联合预测没有优于直接字节重排；它排除不了更强的侧信息预测器，但没有提供达到30 GiB的迹象。

证据：[实测脚本](public_state_audit.py)、[完整结果JSON](public_state_audit.json)、[下载及SHA校验脚本](download_public_state.py)、[固定来源清单](public-state/source.json)。首次下载截断后补齐，最终长度及SHA均验证通过才进行分析。

## 三、能否保证靠当前权重加少量纠正位做到30 GiB

构造了一组可由两次明确FP32 EMA递推达到的状态：梯度来自1,024个固定、可被BF16精确表示的小标量，枚举全部1,048,576对输入。初始权重W0=1，两次更新都因舍入保持W1=W2=1；最终却有1,048,523种不同m/v位串。

如果各参数独立从这组不同状态中选择，解码器只有相同当前W、步号和超参数、不能重算历史，则必须保存足以区分这些状态的信息。均匀族约20位/参数，对应目标N约62.62 GiB，超过30 GiB。这证明不能对所有这类可达情况保证30 GiB；它不证明Qwen实际状态需要20位，更不排除利用额外历史侧信息或历史重算。

## 四、可逆学习文献中的“少量位”为什么不能直接套用

[Maclaurin等，ICML2015](https://proceedings.mlr.press/v37/maclaurin15.html)研究带动量SGD轨迹的逆向计算，使用64位定点整数及有理数动量系数，保存运算丢失的信息。论文还利用速度整数作为信息缓冲，不是直接复现既定FP32 Adam内核。其收益相对保存整条历史计算，不是声称可免费删去当前Adam的m/v。一旦记录跨步增长，也必须计算全部位数及重算代价。

## 判断

目前不能把“纠正位方案”作为30 GiB内的可执行计划。纠正流可能只有约0.62位/参数，但使它这么小所需要的基底仍是两组数；没有发现从现有W免费恢复这些基底的方法。所测完整无损表示最好约52.21位/参数，远高于9.58位预算。

这是对已测试方法的否定结果，不是对所有可能算法或目标Qwen分布的绝对不可能证明。本地训练仓库没有目标模型的真实m/v快照，因此不能给出Qwen专属的精确压缩率。在不运行训练的前提下，能进一步确认模型分布的输入只能是已有、允许读取的历史状态；当前未使用任何私有服务器状态或启动训练来补数据。
