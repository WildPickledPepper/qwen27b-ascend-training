# 原16槽只替换k1 CPU加法

用户要求实测。独立候选基于刚完成的0/3卡86.7923秒复现，训练配置不变：Qwen3.5-27B文本全参、原SQL768条、global256/micro16/16micro、BF16计算与保序累加、CPU FP32 master/m/v、48层非重入重算、4/8GiB驻留及512-token连续化分块loss。三更新首lr0预热、后两步平均，无Profiler。

保留16×128MiB CPU槽、原计算流D2H、FIFO/event等待、CPU累加完成才归还槽。只将CPU worker中的切片`.add_`改成`accum1`调用。没有全参数stash、没有k2合批、没有新增NPU待搬预算或队列改动。原默认及原源码不改。

`slot_kernel.py`只加载原C/OpenMP k1内核、不管理梯度缓冲；OpenMP24线程在真正调用内核的CPU worker内设置。随机有限BF16位模式1048576元素及16次连续累加逐位验证，通过后tiny三更新全grad/master/m/v逐位比较，通过才整模型。源码适配反向替换后必须与86.79秒参考训练文件相同（另加内核调用次数日志）。

物理0/3启动前空闲；CPU144–167/96–119、NUMA6/4与参考相同。结果待完成。参考是在前一轮顺序运行，系统负载可能变化；不把短跑差额当稳定因果收益。完成后退出并检查释放0/3，按持续授权提交结果。
