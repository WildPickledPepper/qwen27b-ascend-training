# CPU更新融合：局部省1.84秒，整轮未获得可靠收益

固定双卡global256、每卡micro16、累积8、相同768条SQL训练数据及顺序/padding，BF16计算、CPU FP32主权重与Adam m/v不变。从95.7402秒/256条配置继续，不改共享安装、原模型或其他服务。

## 改动

原流程分别执行梯度FP32缩放、CPUAdam、读取更新后的FP32主权重生成BF16副本。独立编译的融合扩展在加载梯度时缩放，复用原CPUAdam的NEON表达式、FMA和bias correction，更新后直接从寄存器输出BF16；仍复用两份锁页缓冲异步回传NPU。不再把缩放后的梯度写回，适用范围仅为本次已验证的全参数活跃模型，不能直接推广到稀疏/条件执行参数。

逻辑CPU读写估算从42降到30字节/参数，减少12字节；不是DDR计数器实测。独立源文件SHA256校验、隐藏符号和独立类名避免替换/污染共享库。构建产物不入库。

## 结果与决定

首轮138.59秒为冷启动；正常第二/三轮分别93.7429、97.6692秒，每轮取较慢rank，平均**95.7061秒/256条**。原参考95.7402秒，只少0.0341秒（0.0357%），不足以建立整模型提速结论，未达到本候选1%采用门槛，**不替换原95.74秒默认配置**。第四轮重复首256条仅采样，排除测速。

以下为相同正常两轮rank0宿主调用范围，含对应同步，不是纯NPU计算耗时：

| 每256条 | 原版 | 融合版 | 差值 |
|---|---:|---:|---:|
| 前向 | 16.91秒 | 19.11秒 | +2.20秒 |
| 反向及收尾 | 64.21秒 | 63.82秒 | −0.40秒 |
| 参数更新step | 14.61秒 | 12.77秒 | −1.84秒 |

CPU更新step降低12.57%，但这次前向增加抵消了收益。增加主要出现在第三轮，第三轮前向17.07→21.10秒；没有该正常第三轮的设备采样，不能将增加归因为缓存、通信、CPU融合或硬件竞争。第四轮的正常采样不能冒充第三轮的根因证据。

CPU独立128M元素交替测试为94.755→74.571毫秒（−21.30%）；它不是整模型成绩，也不等于整模型更新step的12.57%。融合后的`optimizer/CPUAdam`范围包含缩放及BF16输出，不能将其12.28秒直接与原仅Adam的10.47秒比较。

## 文件与复核

`build_fused.py`按核对过的DeepSpeed0.19.8 NEON源码生成独立扩展；`probe_cpu.py`包含CPU数值/速度检查，`run_cpu.py`组织该阶段；`cpu_update_fused.py`接入原ZeRO状态管理；`train_fused.py`保留参考入口并增加显式`--fused-cpu-update`。

`run_experiment.py`是本次完整控制器，要求独立新目录、CPU检查先通过、物理2/3卡空闲，先tiny再27B；不自动重跑。`postprocess.py`核对原始数据哈希及工作量并导出过滤证据；本地`collect_result.py`和`finalize_result.py`生成汇总/采用决定。`create_selected.py`门槛未通过，不运行，不生成新默认重放入口。原默认入口及源码哈希已复核不变。
