# CPU常驻FP32主权重与Adam流水

在相同4步短训练/8条独立验证下，CPU主权重流水版后3步平均 **44.51秒**，上一版NPU大窗口76.35秒，约 **1.72倍加速，耗时减少41.7%**；相对最初161.76秒约3.63倍。保持权重、计算、梯度、Adam m/v全FP32，不使用低比特状态或完整BF16模型副本。旧整模型基线直接复用，不重跑。2/3卡已核对释放。

这是短样本协议的后三步均值。上一版还在明显变快，因此同时保留末步：53.37→42.98秒，约19.5%耗时下降；不把1.72倍当已充分预热的长期吞吐。

## 为什么更换状态放置

原实现CPU保存完整FP32 m/v，每次把两份状态搬入NPU更新，再把两份状态搬回CPU。实际26,895,998,464参数对应每步约400.78 GiB状态双向传输。Adam数学本身在大窗口版只约2.01秒，搬运阶段54.77秒。

采用[ZeRO-Offload](https://www.usenix.org/system/files/atc21-ren-jie.pdf)的数据/计算放置思路：CPU常驻FP32主权重、m/v，用优化CPUAdam计算；NPU保留FP32计算权重与前后向。每步只传梯度及更新后的权重，理论主体传输约200.39 GiB。嵌入使用同步CPU路径，微小原生参数沿用参考NPU更新；两份大状态始终FP32，没有量化。

CPU内存代价：主权重约100.20 GiB，m/v约200.39 GiB，合计约300.59 GiB，加上框架及有界锁页工作区。这里NPU权重仍常驻，不把完整权重按层在CPU/NPU之间换入换出。

## 方法与安全边界

- 使用已安装DeepSpeed0.19.8的CPUAdam，编译确认NEON路径。CPU96–119就近24核，保持进程THP关闭；不修改系统全局设置，不宣称CPU页全部在NUMA4。
- 同步CPU版：64 MiB梯度下传、CPUAdam、更新权重中转、回传，逐块等待。有界锁页池，不锁住全部300 GiB状态。
- 流水CPU版：每卡4个slot，每slot一块梯度、一块更新权重，合计约1 GiB锁页CPU缓冲；单CPU更新工作线程与NPU主线程并行。D2H/CPU更新/H2D可以处理不同块。
- 私有扩展仅给CPUAdam的Python绑定增加GIL释放，复用同一已编译数学实现对象；原DeepSpeed源码与共享环境不改。构建脚本保存原源码SHA。CPU工作线程显式设24线程。
- 线性层输入梯度用旧权重算完后才提交更新，CPU工作队列有界；新权重直接写回持久化FP32设备帧。每步排空、核对CPU主权重/设备抽样位串及更新覆盖后，才进入下一次前向/验证。没有延迟一轮使用旧梯度。
- 输入嵌入和微小原生参数保留同步路径。原模型只读；不写回原checkpoint。

## 小测与流水验证

初次双卡33,558,528坐标/3步，对比4/12/24 CPU线程；优化CPU数学有收益，但同步端到端小测尚未稳定超过NPU大窗口。全状态测试相对NPU参考：权重相对L2约1.14e-7、m约2.29e-7、v约1.29e-5，均有限，差异单独保留。该初次小测在CPU扫描梯度有限性；整模型及后续流水小测把同一检查移到传输前的NPU，减少宿主扫描，不把初次适配器与最终源码混称。

流水小测：双卡各100,667,392坐标/3步；设备帧32 MiB、优化器窗口64 MiB，特意测试窗口跨帧、尾部4096坐标和4-slot循环复用。每步全部设备权重、CPU主权重、m、v与同步CPUAdam逐位一致，覆盖数一致。后两步平均：2卡0.12917→0.10912秒，3卡0.12741→0.11029秒，耗时约减少13–15%。这只是小测结果，不能直接外推整模型。

## 复现入口

生成器从已冻结的上轮入口派生新文件，保留模型、数据和审计逻辑：

```bash
python build_cpu_master_entry.py
python build_cpu_pipeline_entry.py
export CPU_ADAM_EXTENSION="$CPU_ADAM_BUILD/cpu_adam.so"
python build_async_cpuadam.py --package "$DEEPSPEED_PACKAGE" \
  --built "$CPU_ADAM_BUILD" --output "$ASYNC_BUILD"
export CPU_ADAM_ASYNC_EXTENSION="$ASYNC_BUILD/cpu_adam_async.so"
export ASCEND_RT_VISIBLE_DEVICES=2,3 OMP_NUM_THREADS=24
python probe_cpu_pipeline.py --output "$PROBE_JSON"
python train_cpu_pipeline.py --model "$MODEL_DIR" --archives "$ENEC_ARCHIVE_ROOT" \
  --data "$INDEPENDENT_SPLIT_DIR" --output "$NEW_RUN" \
  --mode fp32 --steps 4 --eval-count 8 --window 16777216
```

绑定脚本读取既有CPUAdam的build.ninja及实现对象，只在新目录构建。最初未加载训练环境时ninja不在PATH，加载既有环境后构建成功；私有绑定首轮相对输出路径构建失败，改绝对路径后完成。两者均未涉及模型更新。

计时规则：冷步、每一暖步都保留；并行事件/CPU工作时长可以重叠，不能相加当作整步互斥分解。全模型仅4条28–32 token短样本、8条独立验证，GSM8K未进入训练。共享服务器，未宣称长期稳态或硬件极限。
