# 输出层与交叉熵分块：事前显存建模

2026-10-27。用户要求先确认当前是否使用chunked loss，再用显存模型计算收益。本轮只做CPU/meta预测和CPU小张量数值检查；没有NPU初始化、没有加载27B权重，没有上卡训练，也没有修改81.22秒候选。

## 当前没有使用chunked loss

原`sql-pipeline-overlap-20261026/train_resident.py`的fw在rank1调用完整Qwen3_5ForCausalLM，使用`result.loss`。固定Transformers实现先`lm_head(hidden_states)`生成全量logits，再调用ForCausalLMLoss，转FP32后执行普通交叉熵。原脚本中64M-element chunk是梯度卸载/更新窗口，不是loss分块；GDN内部chunk也不是这里的chunked loss。

## 方案与相同输入

沿原27B文本结构、前后各32层、global256/micro16/16micro、48层非重入重计算、每卡4GiB梯度驻留、BF16权重/CPU FP32 master/m/v，采用历史第一组的16个微批长度（192或256）。只对执行输出层的rank1/物理3号卡替换loss路径；rank0不变。

`chunked_loss.py`给出具体的普通PyTorch原型：

1. 沿token位置分块，先取隐藏状态块，再执行lm_head和FP32 CE求和；不是生成完整logits后切片。
2. 正确做causal label shift，忽略-100，各块总和除以全局有效目标token数，避免按块均值等权。
3. 自定义autograd前向只保存完整隐藏状态、权重、标签与计数，不把所有块logits的计算图留下。
4. 反向逐块重算输出层/CE，通过原生autograd求局部隐藏梯度和权重梯度。隐藏梯度写入完整缓冲，BF16权重梯度按块原地累加。
5. 两份完整输出层权重梯度（累加结果、当前块临时梯度）均计入峰值。没有修改参数驻留策略或减少训练参数。

这不是Liger/CCE在NPU上的部署，也不是融合kernel。分块反向BF16求和顺序会改变数值舍入；性能、完整模型质量、与NPU分块内核的布局一致性尚未验证。

## 预测结果

使用当前`storage_tracker.py`及固定NPU matmul布局规则，重新计算完整loss对照和四个分块版本，各自执行完整16micro。预测封存并校验SHA后导出比较；没有读取新上卡观测。

| 每块token位置数 | 3号卡峰值GiB | 相对完整loss省GiB | 峰值降幅 |
|---|---:|---:|---:|
| 完整loss | 54.0541 | 0.0000 | 0.00% |
| 256 | 47.5832 | 6.4709 | 11.97% |
| 512 | 47.7040 | 6.3501 | 11.75% |

块大小指整个microbatch展平后的token位置数，不是词表大小，也不是每条样本的长度。S=256时16×256=4096个位置，512块对应8块；S=192时3072个位置对应6块。序列上下文仍由完整Transformer计算，不拆注意力上下文。

256比512只再省约0.121GiB，模型不能判断这点空间是否值得更多重算/下发；不据显存数字选速度最优。

## 从存活张量解释收益

词表V=248320，隐藏维H=5120。micro16、S256时，完整FP32分数矩阵占：

`16 × 256 × 248320 × 4 = 4,068,474,880 bytes = 3.7890625 GiB`。

完整路径的峰值含三份该形状张量：log_softmax结果、nll_loss反向结果、log_softmax反向结果，共11.3671875GiB。

分块并不意味着这11.37GiB全部消失。每份完整BF16输出层权重梯度是：

`248320 × 5120 × 2 = 2,542,796,800 bytes = 2.3681640625 GiB`。

256/512/1024版本的新峰值处，两份梯度同时存活，共4.736328125GiB，此外还有隐藏梯度和当块张量，所以净省约6.1–6.5GiB。2048版本仍以当块CE反向张量为主要峰值，节省较少。峰值已由实际meta存活集合确定，没有直接按原11.37GiB乘分块比例。

这是3号卡独立峰值下降；2号卡原峰值约56.56GiB且不变，因此两卡中最大单卡峰值不会下降到47.7GiB，不能把3号卡释放空间转移给2号卡。将空余空间用于更多梯度驻留是另一个调度方案，不在本轮混入。

## 验证与边界

CPU小张量共10项，覆盖FP32/BF16、块大小1/4/7/18/32、非整块尾部、完全忽略标签的块、causal shift与归一化。loss最大差4.77e-7；FP32权重梯度relative L2最大约6.97e-8；BF16权重梯度最大约0.394%，隐藏梯度与参考相同。只是小张量数值接入检查，不代表27B整模型/NPU精度或收敛验证。

预测未启动NPU、不加载权重；完整rank1参数梯度回调425/426参数结构及16micro覆盖检查通过。allocator粒度沿用前一版本从历史轨迹提取的规则，属于已知测量输入，不包装成新推导的物理分配器；对照与候选使用同规则并同时报告逻辑申请值。

CANN内部workspace、运行时基础占用、reserved/碎片和任意异步释放仍不覆盖。meta没有计时意义，不声称预测能加速；本原型增加输出层重算、分块权重梯度计算，存在速度代价。
