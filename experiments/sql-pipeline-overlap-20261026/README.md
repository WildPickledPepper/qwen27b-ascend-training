# 流水线剩余瓶颈：复制流解耦

2026-10-26用户授权继续优化85.09秒流水线，要求ms定位并估算剩余空间。固定原768条/顺序/padding、global256/micro16、16个流水线micro、48层重算、每段2GiB BF16梯度驻留、CPU FP32 master/m/v、原更新次数及累加顺序；只用实时空闲物理2/3卡，独立目录，不改共享库、原checkpoint或既有候选。

## 旧数据给出的具体机会

旧rank0 ms窗口91.94秒：计算覆盖39.53秒，未与计算重叠的通信10.19秒，既无计算也无通信的复制15.23秒，其他26.99秒。四类互斥，合计窗口；采样91.94秒不代替正常85.09秒。

计算与全部MEMCPY_ASYNC均在stream254，重叠为0。反向宿主范围内复制13.89秒，rank1为14.01秒；这支持独立D2H流重叠，而不是凭框架名称猜收益。该范围是与宿主反向区间的时间相交，不把异步设备事件强行当宿主调用的子节点。

正常rank0 CPU BF16累积51.22秒、等接收槽34.65秒，更新收尾约17.34秒；这些有重叠，不能相加。ms更新范围中rank0无设备任务14.93秒、rank1为15.80秒：优化复制不会自动消掉CPU Adam。通信事件也含等另一段的时间，不能把10.19秒全当链路传输瓶颈。

因此本次只针对反向复制串行：采样中约14秒是完全隐藏这部分复制的乐观上限，不承诺正常轮一定减少14秒，更不能宣称所有非计算时间都可消除。CPU累积及更新仍形成后续限制。

## 候选与验证门槛

梯度产生后，在主流记录ready事件，独立复制流等待它；固定16个锁页接收槽复用规则不变。源梯度通过`record_stream`保留到复制完成，CPU worker等每个复制事件、按原FIFO逐次BF16相加，再归还接收槽。全部micro结束仍先排空，再全局裁剪和更新，禁止提前更新权重。

小模型同时覆盖驻留及非驻留参数，连续三次完整梯度/master/m/v须与原流水线逐位一致；通过后才跑27B前三正常轮（第一轮预热）及第四轮ms采样。新采样增加等槽及CPU累积标记和逐参数时间计数；若worker标记没进入Profiler，报告缺失，不当零耗时。
