2026-10-26用户授权压缩当前27B训练对应的BF16权重，验证能否为NPU梯度累积释放空间。本次先做实际完整文本权重的独立压缩归档、NPU字节校验与编解码计时，不改现有81.22秒训练入口，不改原checkpoint、共享环境或作者内核。

## 数据和方法

按已完成4GiB流水线任务的两段实际manifest，各自处理前/后32层及embedding/lm_head，合计851张量、26,895,998,464参数。读取原checkpoint，按训练初始化相同方式转换为BF16计算字节；不先扩展FP32。原训练768条后的权重没有保存，本归档明确是源checkpoint的BF16计算权重，不冒充训练后状态。

固定作者提交`3026adde1ed97f8ae528515ae9de9de60e89176a`，使用其现成`ENEC-BF16-122-6-3-16`内核，仅修改ACL宿主包装的BF16类型、32768-byte块等参数。原始kernel五项哈希在构建清单记录，复制前后逐字节核对，不执行作者的设备reset/安装脚本。

64MiB最大原始帧，所有帧先压缩、解压、比较原BF16字节。作者回环有位差或编码膨胀则存原始BF16字节；小张量原样存储。原字节回退属于最终格式的一部分，不能把回退块说成作者codec通过。Header、raw fallback和JSON映射计入最终容量。

## 顺序门槛

先在空闲物理2卡测试完整65536种uint16位型（覆盖BF16零、次正规、Inf、NaN payload）、全零、未对齐尾块及真实模块样本。样本出现真实压缩帧且输出可无损保存后，再在实时空闲2/3卡分工完成整个模型；每卡完成后独立重新打开保存文件，在不载入原权重的情况下解码、核对原始SHA和全部帧/张量范围。

作者kernel在独立目录编译完成、probe通过最终格式无损门槛，随后完成两段全量归档及独立全帧回读。probe全位型、全零、未对齐尾样本和真实embedding样本均出现作者回环位差，使用原字节回退，不能声称作者codec对任意BF16都逐位通过。

NPU事件累加包含最终回退的大帧尝试，不是“线上每步解压模型只需0.135秒”的证明。事件围住作者launch及必要队列工作；不是只含AI Core指令busy时间。宿主wall还包含分配、主机/设备复制、CPU校验和下发等待；与NPU事件嵌套，不能重复相加。训练有16个micro及前向/重算/反向多次权重读取，不能套用一遍事件总和。

本harness显式设备分配峰值每卡362,334,144 bytes（345.55MiB），包括原始、两份压缩/临时区和解压缓冲共存。这是分块离线测试，不是驻留整个压缩模型后的线上峰值，也不能拿它直接扣出线上训练可增加的缓存量。

## 归档、重放及后续边界

服务器本案例目录下`full-card2.private/`、`full-card3.private/`各保存`weights.bf16.enec.parts`、`report.json`、`archive_verification.json`。前两者定义恢复格式：张量形状、元素偏移、帧偏移、编码/原字节类型及输入/保存SHA；不能单独对拼接parts调用作者CLI解整个文件。

可在新目录复用本案例，先配置原独立CANN/Python环境，再运行：

```bash
python build.py --source "$ENEC_SOURCE" --sdk "$CANN_SDK" --cmake "$CMAKE_BINARY"
python run.py --model "$MODEL_DIR" --reference "$PIPELINE_REFERENCE" --device 2 --mode all --output "$NEW_ARCHIVE"
python verify_archive.py --archive "$NEW_ARCHIVE" --device 2
```

物理3卡同理分工，不重复计入同一张量。`NEW_ARCHIVE`必须不存在，不覆盖原模型或已有归档；编译产物与作者源码不入Git，固定提交及五个kernel源文件SHA在报告中。

完整过滤证据：[全量容量、回读与计时](../../evidence/2026-10-26/bf16-enec-full-summary.json)、[probe及原字节回退](../../evidence/2026-10-26/bf16-enec-probe.json)。2/3无运行进程，未操作其他任务。本次完成的是无损归档；若要实际增大梯度缓存，必须让模型按需解压、释放普通BF16持久副本，并扣除解码工作区，再验证当前固定256条训练的数值与净速度。本轮未启动该训练集成。

## 计时和空间口径

分别保存压缩、merge、解压NPU事件时间，以及离线roundtrip宿主wall；二者不能相加。离线wall包含设备分配/H2D/D2H等，不能当训练中的纯解压开销。本测试同时保留原始、压缩、临时和解压缓冲，实际占用没有因归档压缩而自动下降。

归档净节省不含未来训练的解压窗口、调度元数据及可能重复解码工作。本次不将完整BF16副本与压缩副本同时常驻后宣称省显存，不据离线压缩率承诺整模型加速。

只用自身账号的独立目录，原权重只读、结束释放自己的进程；不操作其他卡任务。权重归档、原始日志及编译产物不入Git，提交可移植包装/验证脚本和过滤结果。

参考：[ENEC作者实现](https://github.com/hpdps-group/ENEC)、[论文](https://arxiv.org/abs/2604.03298)。本机结果以实测和逐帧字节校验为准。
