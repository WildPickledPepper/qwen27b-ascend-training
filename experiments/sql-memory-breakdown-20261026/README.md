## 为什么是这些数

### FFN：2卡7.96875GiB，3卡4.25GiB

分配栈落在实际Transformers `modeling_qwen3_5.py:736` MLP实现：`down(silu(gate(x))*up(x))`。这里同时留下gate、up、silu结果和门控乘积四类大张量。单份典型形状16×256×17408，BF16：

`16*256*17408*2 = 142606336 bytes = 136MiB`。

2卡峰值60份、合计7.96875GiB，3卡32份、合计4.25GiB。它们是前向生成且在峰值仍存活的块，不是FFN参数，也不是FFN权重梯度。部分checkpoint重算的同类张量另列在重算行，避免重复计数。

### RMSNorm：2卡9.14809GiB，3卡5.07433GiB

实际实现`_norm(x.float())`，随后FP32缩放再`type_as(x)`。BF16计算模型不代表这些中间结果全是BF16。分配栈定位到747/750/753/754行，包含归一化FP32中间结果、逐token统计量、缩放结果以及转回BF16的结果。它们是激活/中间张量，不能误算成很小的norm参数。

这里还包括注意力Q/K的RMSNorm，非只有两处layernorm。表内与checkpoint重算的norm分开计。

### 普通注意力：2卡6.328125GiB，3卡3.375GiB

实际使用eager attention。2卡峰值分项：FP32 softmax1.40625GiB，门控相关中间结果1.40625GiB，旋转位置编码0.703125GiB，展开K/V合计1.40625GiB，转回BF16的注意力概率0.703125GiB，以及注意力输出矩阵乘结果0.703125GiB。合计6.328125GiB。Q/K norm已经在RMSNorm行，不再计一次。

### 隐藏状态与重算

2卡1.9921875GiB包括层间残差/隐藏状态、checkpoint边界保留和流水线用的输入输出；3卡0.9375GiB。2卡在该峰值正处于反向并触发一个checkpoint层的重算，所以同时还有1.567513GiB重算中间结果；3卡峰值在损失反向，重算项在该时刻为零。

两段1F1B调度中，2卡可同时保有上一微批待反向的图和当前微批的图，不能按一份前向激活估算。两卡不同阶段的存活图数量不同，也解释了FFN/Norm/Attention占用差异。

### 反向临时梯度：必须区分参数梯度和激活梯度

2卡峰值：matmul backward的两块输出0.298828125GiB，参数梯度累加临时块0.166017056GiB，autograd InputBuffer合并0.0390625GiB，共0.503907681GiB。大块尺寸与当前FFN的权重/中间梯度对应；这是当前反向节点的临时结果，不是整个半模型的全量梯度常驻。分配来源包括native MatmulBackward、AccumulateGrad、InputBuffer。

3卡最显著：`NllLossBackward0`与`LogSoftmaxBackward0`各分配3.7890625GiB，合计7.578125GiB，都是词表输出方向的临时梯度，不能说成7.58GiB参数梯度。同时前向交叉熵保留的log-softmax结果还有3.7890625GiB，因此**损失计算链在该峰值共11.3671875GiB**。

单份与实际形状严格对上：`16*256*248320*4 = 4068474880 bytes = 3.7890625GiB`。最后的4字节是FP32；词表248320。不是Adam m/v，也不是推理KV cache。

## 方法、误差和验证

独立`train_memory.py`由原入口只添加allocator history、持久张量storage标记及初始/结束pickle生成；原48层重算、训练数学、CPU FP32 master/m/v和更新边界未改。记录完整Python/C++分配栈与alloc/free_requested生命周期，初始活跃块作为种子，从头重建同一事件处的存活集合。

218770/219672个alloc事件全保留，没有环形历史截断。重建结束时两卡allocated与框架计数逐字节相同；trace requested size按512B对齐后，重建峰值比框架峰值分别少280576/141312字节（0.268/0.135MiB）。这部分未硬塞进激活或workspace，明确保留为对账差额。因此这是GiB尺度已闭合、仍保留亚MiB块口径差额的账，不能声称每个峰值块的真实尺寸都已精确还原。

分类优先使用更内层的checkpoint重算/具体前向调用，原生反向分类限制为无Python前向栈的块，避免把重算张量仅因外层MatmulBackward调用而算成梯度。前向中间张量的含义是前向申请且峰值仍存活，没有另加saved-tensor hook改变原checkpoint。

原第一轮与旧四轮最大峰值仅差约0.00026GiB，不把这一亚MiB差值伪装成大块变化。一次原配置诊断，不承诺覆盖未来更长序列或所有训练步。

**直接得到的下一步研究目标**：2卡先关注非融合RMSNorm的FP32中间结果及保留图；3卡先关注非融合词表交叉熵的11.37GiB损失链。此次只做拆账，未修改它们，也不把全部占用当作可无代价释放的容量。
