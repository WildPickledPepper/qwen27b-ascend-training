# 原4GiB流水线动态显存拆账

按用户要求，排除压缩版，对原81.22秒候选的激活、临时梯度和算子工作区进行分配生命周期分析。物理2/3实时空闲检查后启动，独立入口只添加NPU allocator history和初始/整轮结束快照；原入口、原权重、训练数学及其他任务不改。

固定原第一轮256条、micro16、16流水线micro、48层重算、4GiB梯度驻留、BF16计算/累积和CPU FP32 master/m/v。只跑一轮显存诊断，不重新评选训练速度。历史第一轮两卡峰值56.55997/54.05422GiB，与历史四轮总峰值仅差约0.00026GiB，先以本轮第一轮核对可复现性。

从初始活跃分配开始重放alloc/free_requested，核对重建的最终allocated及峰值必须与框架计数一致，再分类同一峰值时刻仍然存活的块。权重/常驻梯度按真实storage地址标记；动态块保存Python/C++分配栈，按调用来源继续核对。不能把不同时间的各类峰值相加，也不能把所有未知余额直接叫激活或工作区。

原始快照、地址、私有路径、完整数据日志仅留服务器；提交去标识聚合与可移植分析脚本。当前正在采集，尚无动态细分结论。
