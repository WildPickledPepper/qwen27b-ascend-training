# 双进程ZeRO-3与CPU FP32状态卸载

2026-10-25用户授权“试试”。仅使用实时空闲的物理2/3号910B2，原模型只读，不修改共享安装，不自动Git提交/推送。目标是同时计算不同训练样本，而不是旧单进程按容量分配矩阵。

## 精度和训练协议

使用原模型文本结构Qwen3_5ForCausalLM，26,895,998,464参数；视觉与MTP不加载。原safetensors按张量加载，ZeRO初始化/加载只临时收齐一个张量，不在某张卡先建立完整FP32模型。

- 计算模型使用原生BF16，包含与旧“仅线性BF16、其余FP32”不同的敏感运算路径。验证数值单独记录，不能把两个实现当完全同精度配置。
- 主权重和Adam m/v全部FP32、分片驻留CPU，不量化、不做ENEC、不用NVMe。
- HCCL两进程数据并行，ZeRO-3管理权重/梯度/状态分片，通信归约指定FP32。
- 禁用旧即算即更新钩子；框架先汇总/累积梯度，完成全局更新。局部loss按全局assistant token数加权，避免不同样本长度导致按rank等权偏差。
- 固定全局batch=2。双卡每卡1样本；单卡每次累积2个样本。每组4次更新、相同8条短训练样本、独立8条验证。没有训练验证混用或GSM8K。
- lr=1e-5、AdamW(.9,.999)、eps=1e-8、wd=.01、无全局梯度裁剪、种子20261024、序列≤128。使用非重入activation checkpoint。
- 2/3卡共同靠近NUMA4 CPU96–119；双卡各12个不重叠核心，单卡24核心。两组均设TASK_QUEUE_ENABLE=0，避免把此前下发队列差异混入比较。

复用已编译验证的CPUAdam.so，在实验进程中替换Builder.load为直接加载；数学实现不变。旧JIT目录有遗留lock，本轮没有删除/修改它。默认缓存加载的小测因此被主动终止，复用二进制后双卡小模型两次完整更新成功，master/m/v dtype与设备断言通过。

## 代码

- `zero3.json`：优化器CPU卸载、权重不卸载、分块归约/预取、通信重叠。
- `train_zero3.py`：双卡启动与首次完整模型验证。
- `train_zero3_compare.py`：同全局batch的单/双卡入口；单卡自动累积2个microbatch。
- `launch.sh`：双卡独立启动模板，模型、数据、环境和二进制由环境变量指定。

首次双卡已完成4步，后3步约42.01秒/两个样本，验证loss2.04857→1.50442。原生单卡同全局batch对照在首次反向OOM：57.28 GiB已分配时，DeepSpeed整张嵌入梯度转FP32额外申请4.74 GiB，只余3.16 GiB，不能给出同口径加速比。

## 有界梯度转换适配

在实验进程内替换DeepSpeed `_offload_grad_partition_at_boundary`中唯一的整张梯度转换/复制调用，改为每16,777,216坐标（FP32临时64 MiB）的转换与复制。保留原梯度范数、目标FP32梯度存储、更新时序及Adam；不修改共享源码。源代码特征不匹配就报错，不静默套用。

BF16及FP32输入各16,777,473坐标、含非整窗口尾部的小测，输出FP32梯度与原调用逐位相同。带此适配的单卡小模型、全局batch=2、两次更新通过。随后用同一`train_zero3_bounded.py`顺序运行单卡和双卡，各4步；先确认单卡容量，再运行匹配双卡，保留首次双卡与单卡失败。

所有性能数字按完成状态和实际样本量统计，不预先宣称加速；有界转换的位级测试不等于长期整模型训练逐位一致。

单卡有界组已通过原OOM位置并完成更新；日志每步报告4次allocator cache flush，峰值接近设备可用容量。最终单/双卡差异包含容量压力与实际并行收益，不仅是计算量分摊，不将吞吐加速比解释为纯通信/计算效率。

## 完成结果

有界适配后的单卡与双卡均从原始权重开始，各完成4次更新，正常退出码0。两个样本合为一次全局更新，使用相同8条训练样本（28–44 tokens）、相同独立8条验证；提示和回答合计276个输入token。训练loss按全局assistant token数加权。完整过滤证据见[结果JSON](../../evidence/2026-10-25/zero3-offload-results.json)。

排除首步后，双卡吞吐为单卡的1.50088倍，单次全局更新耗时减少33.37%。各步全局训练loss的最大差约2.38e-7；两组最终验证loss在本次输出精度下相同，但8条短验证不证明长期训练质量或全参数逐位一致。

每次更新之后检查CPU FP32主权重及Adam m/v；全部rank的m/v字节数之和为215,167,987,712，等于26,895,998,464参数×两份FP32状态，未量化或减少状态字节量。单、双卡共用同一分块转换入口及ZeRO配置，仅进程数/梯度累积/CPU核心分配随并行度调整。两组task queue均为0。

本次相对于旧单进程模型分布的改变是标准数据并行、ZeRO状态分片、两进程CPU更新和框架梯度汇总；并非把旧53.88秒直接降为41.64秒，因为旧配置每步只有一个样本，且计算实现不同。正式比较只使用上表同全局batch对照。相同总代码和数学设置不意味着每项底层执行顺序逐位相同。

## 边界与结束

这是4次更新、8条短训练样本的吞吐验证，尚未测更长序列、更大batch、稳定长跑或Profiler关键路径。单卡有每步4次allocator cache flush，双卡收益包含缓解显存压力；没有用隔离实验把1.50倍逐项归因，不称硬件上限。

两个正式组均正常退出，复核物理2/3卡无活动进程，HBM分别回到3417/3416 MiB基础占用；未终止其他任务。原始模型不变，本轮没有保存新的完整checkpoint。仅更新工作区，不自动Git提交/推送，不继续启动训练。
