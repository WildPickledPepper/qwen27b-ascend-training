# 流水线梯度累积与卸载：有界NPU驻留

用户要求先优化现有两段流水线的梯度累积/卸载，再评估双卡张量并行。原固定256条、micro16、16个流水线micro、原768条/padding、BF16计算和CPU FP32主权重/m/v不变；默认ZeRO-3暂不改。

上一轮正常rank0 CPU BF16累积58.06秒，主线程等接收槽43.53秒，每段约430.34GB梯度D2H逻辑字节。候选按每段2GiB硬预算选择完整参数的BF16梯度，在NPU按原micro顺序逐次相加，16个micro结束后只卸载一次。未选中的参数完全沿用原CPU队列。CPU目标对驻留参数保持为零，最终复用原锁页槽/生产者event/FIFO worker；不提前更新权重。

先利用原正常tiny作为参考，不重跑基线。新tiny部分驻留、部分CPU：连续三次更新，两rank全部梯度/master/m/v逐位一致；首步相对未切分模型及独立范数检查也通过。27B四轮测试进行中，前三轮正常计时、首轮预热，第四轮单独双rank Level1/Db采样。尚无整模型加速结论。

入口由`build_entry.py`从原匹配初始化流水线派生，原入口不改；`resident_gradients.py`是有界策略，`compare_states.py`检查三步完整状态。原始DB/数据/权重/路径/完整日志和tiny状态不提交，仅过滤证据归档。
